# Generic offline preview

`loader::load` reads the fixed `preview.jsonc` catalog and standalone ATX1 resources through an already retained World `SourceRoot`. The catalog is strict `tilewright.editor-preview/1`, with closed keys, duplicate rejection, explicit MIT resource provenance, checked dimensions, exact hashes and bounded counts. Resources become an immutable in-memory renderer provider. It never opens files or invokes callbacks while rendering.

`PreviewCatalog::editing()` exposes validated UI capabilities. Grants are deny by default: `movable_uids` and `fields` grant per uid, and the optional `objects` list grants per prototype. Each `objects` entry is `{proto, layer, fields?, defaults?}`: `proto` must be a catalog prototype, `layer` a profile render layer, and `fields` lists the NAMES of profile object fields that may be edited (a grant, like `editing.fields`; it carries no values); unknown members, duplicate prototypes and duplicate field names are refused. `defaults` is an object of field values a newly placed object of the prototype receives, for profiles whose schema requires fields. Its names must be profile object fields (they are written under the new object's `fields` member, so a field may share a name with an object member such as `layer`); scalar values must match their field's type, range, length, choices or reference target, and `list`, `object` and `json` values must have the right JSON kind. World validates the whole new object again when a placement is prepared, nested values included, and refuses it there. Defaults keep their catalog order as canonical JSON (`ObjectGrant::defaults`), within a 64 KiB budget per entry that counts the canonical bytes of the values, not the names. An entry without `defaults` loads exactly as before. One entry lets the author delete, move and edit the named fields of objects of that prototype, but only of top-level objects in the active view: the catalog's plane and spatial layer, with the object's tile inside the view bounds (`PreviewCatalog::in_active_view`). `PreviewCatalog::can_delete`, `can_move`, `can_edit_field` and `editable_fields` apply that scope to per-prototype grants and combine them with the per-uid grants, which keep their own reach. An entry also lets the author place objects of its prototype, with its `layer` and `defaults`, on tiles inside the same active view (`PreviewCatalog::tile_in_active_view`). A catalog without `objects` loads and behaves as before and grants no deletion. The optional `zones` member is `{paint, manage}`, two required booleans and nothing else: `paint` grants the zone brush in the active view, `manage` is parsed and kept (`EditingCapabilities::zones`) but grants nothing yet. They are capability flags, never zone ids, so a catalog keeps loading when zones are added or removed. A catalog without `zones` grants nothing about zones. `ReadyResources::prototype_texture` returns the ready texture identity a prototype is drawn with, for UI previews such as palette thumbnails; it is the same entry of the same provider, so nothing is loaded twice. The catalog's exact text digest and resource digest vector are independent of `World::source_digest()`: World does not include preview sidecars in its source revision. Call `loader::revalidate` before preparing commands, accepting publication or picking, and require an explicit reopen after mismatch. Holding a previously loaded catalog does not validate changed source files.

`prepare` is pure. It converts the selected plane/spatial layer and bounded view into the released renderer's `WorldView`, then invokes its compiler for projection, height stretching, layer/sub-layer ordering and screen geometry. Global chunk coordinates use checked arithmetic; the released terrain transition resolver supplies derived tiles. Objects require UIDs and explicit render layers. Unsupported visible objects, missing mappings and incompatible ground-layer ordering return errors. Inventory and unimplemented visual field/effect interpretation produce bounded diagnostics. Preview v1 deliberately uses one-tile footprints and neutral effects.

`SelectionKey` is stable semantic identity. Numeric IDs are allocated in sorted semantic order and are deterministic only within the prepared scene. Renderer input retains placed-object source order independently, with terrain emitted before explicit objects; this preserves final draw-order ties. Every frame generation must be nonzero and advanced by the session when source, view or camera changes. The main semantic mask selects objects or populated terrain. A second, undisplayed scene has an opaque reference tile for every cell of `ViewSpec::grid`, including empty terrain, with the identical camera and height field. Its authored reference square/diamond art is projected and rasterized exclusively by the shared renderer. `PreparedPreview::pick` runs released `ReferenceRenderer` on demand and rejects stale generations and out-of-viewport coordinates. The native shell converts logical pointer coordinates to physical pixels once and revalidates the loader before using the result.

The CPU reference path provides exact picking and deterministic proof; native display remains the application's released GPU renderer responsibility.
